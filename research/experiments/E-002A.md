## 1. 研究问题与解释边界

E-001 已证明 128 个可靠分布对应足以重建 GDROS 的最终仿射。E-002A 只回答第二个问题：
冻结 checkpoint 的 post-Transformer 特征是否包含可被 `K x N` 稀疏全局解码器直接读取
的对应信号。

本实验无训练。raw hard-argmax + ordinary LS 是零超参数主探针，但它的失败只否定最简单
解码器。RAFT/GDROS 特征原本用于相关金字塔的局部迭代查询，并未被训练成全局 argmax
描述子；普通 LS 又不能承受离群点。因此只有分层诊断全部判负后，才能判定冻结特征探针
失败，且不能将整个 SparseGeo 方法族登记为失败方法。

## 2. 特征路径与部署对象

正式输入为 optical/SAR `[B,3,512,512]`，沿用官方归一化和 checkpoint：

```text
BasicEncoder
  -> 1x1 channel converter
  -> position encoding + FeatureTransformer
  -> optical/SAR [B,256,64,64]
```

实现两个对象：

1. `reference-hook`：从完整 GDROS 取得 post-Transformer 特征，只用于正确性对照。
2. `slim-execution`：只注册实际执行的 encoder、converter 和 FeatureTransformer，物理移除
   context、CorrBlock、GRU、upsampler 和未执行的 `cost_perceiver_encoder`。它必须与
   `reference-hook` 逐元素一致，正式资源结果使用该对象。

删除未执行模块属于部署清理，不作为论文方法贡献。报告完整 checkpoint 参数、registered
参数和 active 参数三种口径。

## 3. Anchor 定义

主 anchor 使用 E-001 的 `public_stratified` 静态像素坐标。对每个像素 anchor `(x,y)`，
在仍属于公开 `[10000:210000]` 点池的 stride-8 token 中选择使
`(8xf-x)^2 + (8yf-y)^2` 最小的 token；距离并列时按 `(yf,xf)` 字典序选择。映射后必须
恰好得到 K 个唯一 token，否则停止并返回方法讨论任务。映射结果保存为 JSON 和 SHA256，
所有 424 对复用同一集合。

feature token 是否属于公开 pool 按其代表像素的 row-major 索引
`(8*yf)*512 + (8*xf)` 判断。

- 默认：K128，对应 E-001 的 `8 x 16` stratified 设计。
- Pareto：K64、K256。
- Coverage diagnostic：K128 全 `64 x 64` feature map 分区中心，使用相同的最近 token 与
  字典序规则，不进入主门槛。

source 和 target 均不使用图像内容、GT、valid mask 或黑边过滤。GT-in-bounds 子集只用于
诊断图外对应的影响。

## 4. 主匹配和普通 LS

原生主路径：

```text
source = optical_feature.flatten(2).transpose(1, 2)
target = sar_feature.flatten(2).transpose(1, 2)
anchors = source[:, anchor_indices]
scores = anchors @ target.transpose(1, 2) / 16
target_index = hard_argmax(scores)
```

只在取得 source anchors 后计算分数。默认 target chunk 为 1024；chunked argmax 只在新值
严格大于旧值时更新，以保持 `torch.argmax` 首次命中语义。K128 完整分数仅 524,288 个
FP32 元素，即 2 MiB；任何正式路径不得出现 `4096 x 4096` 张量。

方向固定为 optical source 到 SAR target，flow 为 `target-source`。token `(xf,yf)` 对应
像素 `(8xf,8yf)`，不是 `(8xf+4,8yf+4)` 或 `511xf/63`。

在 `[-1,1]` 归一化 lattice 坐标中，用 FP32 `torch.linalg.solve(X^T X, X^T Y)` 求普通
仿射。令：

```text
N(h,w) = [[2/(w-1), 0,       -1],
          [0,       2/(h-1), -1],
          [0,       0,        1]]

H_lattice = inverse(N) @ H_norm @ N
H_pixel = P @ H_lattice @ inverse(P)
flow(x,y) = (H_pixel @ [x,y,1])[:2] - [x,y]
```

原生 1/8 的 `P=diag(8,8,1)`。所有设计矩阵必须 rank 3，并记录条件数。

## 5. 预注册非主诊断

所有选择在查看 E-002A 正式结果前固定，不依据 424 对测试集调参。

### 分数与解码

1. `cosine-hard`：L2 normalize source/target，cosine 后 hard argmax。
2. `raw-local-soft`：raw hard top1 周围 `5 x 5`，以 `softmax(score/1.0)` 得连续坐标。
3. `cosine-local-soft`：cosine hard top1 周围 `5 x 5`，温度 `tau=0.1`。
4. `K-anchor-dual`：K128 raw 分数上
   `softmax_target(S/1.0) * softmax_anchor(S/1.0)`，再 hard argmax。该操作只让已选 K 个
   source anchors 竞争，正式名称固定为 `K-anchor dual normalization`。

局部窗口靠近边界时只保留落在目标 lattice 内的 token，并在这些有效 token 上重新归一化，
不得通过重复 padding 引入额外概率质量。

全局 soft-argmax 的多峰期望可能落在不存在的位置，不作为通过门槛。可以记录为负面对照，
但不得据此否定方法。

### 分辨率

1. `1/16-decimation`：post-Transformer `f[:,:,::2,::2]`，`P=diag(16,16,1)`。
2. `1/16-average-pool`：`avg_pool2d(f,2,2)`，
   `P=[[16,0,4],[0,16,4],[0,0,1]]`。

二者只运行 K128 raw hard，并映射到各自合法 lattice。它们不会减少 Transformer 计算，只
用于判断粗分辨率是否仍保留全局匹配信号。

## 6. GT 诊断和检索指标

GT 从不进入正式匹配或求解。GT 对应在 anchor 代表的整数像素位置读取：原生 1/8 为
`(8xf,8yf)`，1/16 average-pool 为 `(16xf+4,16yf+4)`。连续 target 等于 source pixel 加
truth flow。对 target 满足 `0<=x<=511, 0<=y<=511` 的 anchor，报告 raw 与 cosine：

- `R@k,r`，其中 `k=1,2,4,8,16,32,64`，主半径 `r=1` feature cell，辅助 `r=2/4`；
- nearest target lattice token 的 exact-rank、MRR、median rank 和 P90 rank；
- top1 endpoint error CDF：8/16/32 px；
- row margin、entropy 对 top1-inlier 的 AUROC/AUPRC；
- 每对按 margin/entropy 选 top16/top32 后的 inlier precision；
- target collision：唯一 target 比例、最大复用次数；
- target feature norm 与错误率、被匹配次数的相关性；
- GT-in-bounds anchor 比例和空间分布。

置信区间以 image pair 为 bootstrap 单位，不能把同一图像的 128 个 anchor 当成独立样本。
top1-inlier 定义为与连续 GT target 的 `L_inf` 误差不超过 1 feature cell。

### 三类 oracle

1. `continuous-GT oracle`：连续 GT 对应直接拟合，检查方向、共轭和 solver。
2. `nearest-lattice oracle`：使用最近 `64 x 64` target token，量化 stride-8 下限。
3. `top-k candidate oracle`：从真实 top-k 中选离 GT 最近的候选，同时报告：
   - `select-all`：保留全部 anchor；
   - `select-and-reject`：只保留误差不超过 1 cell 的 anchor。

第三类只证明候选集合包含答案，必须标记 GT diagnostic。

## 7. 几何与局部可恢复性

除公开 AEPE/CMR/P95/P99/failure 外，在每对图像的 `16 x 16` 均匀网格报告：

- mean 和 P95 仿射向量重投影误差；
- 四角最大 `L_inf` 误差；
- `capture@32`：误差不超过 32 px，即未来 `1/8`、`9 x 9` 局部窗口可捕获的网格比例。

定义：

```text
PairLocalReady =
    grid P95 <= 24 px
    AND corner max <= 32 px
    AND capture@32 >= 90%
```

## 8. 分层门槛与决策树

### G0：实现门槛，强制通过

- slim/reference feature 最大绝对差为 `0`；
- chunked/unchunked K-row score 最大差不超过 `2e-5`，top1 一致；只有 margin `<1e-6`
  的数值并列允许例外；
- 设计矩阵均 rank 3，归一化条件数不超过 10；
- continuous-GT oracle：AEPE `<=1e-3 px`、P99 `<=1e-2 px`；
- nearest-lattice oracle：AEPE `<=1.0 px`、pair P95 `<=2.0 px`，无 `>5 px` 失败对；
- 全部样本无 NaN/Inf 或静默 solver 失败。

G0 失败属于实现或坐标错误，禁止解释方法。

### G1：直接精度快路径，充分但非必要

任一预注册非 GT 分数满足以下完整精度条件，或至少 90% 图像满足 `PairLocalReady`：

- AEPE `<=1.56123 px`；
- CMR@1 相对 baseline 下降不超过 2 pp；
- CMR@2 下降不超过 1 pp；
- CMR@5 下降不超过 0.5 pp。

满足则下一版本可直接进入 `E-002B/B1`。不满足不能停止，继续检查 G2 至 G4。

### G2：top1 置信度可恢复，对应 B1

同时满足：

- `R@1,1-cell >=25%`，`R@1,2-cell >=40%`；
- 至少 90% 图像拥有不少于 12 个 top1 inlier，覆盖至少 3 个象限，条件数不超过 20；
- margin 或 entropy 至少一种预注册信号的 inlier AUROC `>=0.70`；
- 至少 90% 图像中，按该信号选择的 top32 anchors 的 inlier precision `>=60%`。

满足说明 hard top1 中已有可用子集，下一版本应实施 confidence WLS 和 Huber/Student-t IRLS。

### G3：top-k 候选可恢复，对应 B2

G2 不通过，但同时满足：

- `R@8,1-cell >=40%`，`R@32,1-cell >=65%`，`R@64,2-cell >=80%`；
- 至少 90% 图像有不少于 16 个 top32 可恢复 anchor，覆盖至少 3 象限，条件数不超过 20；
- top32 `select-and-reject` oracle 的网格 mean `<=4 px`、P95 `<=8 px`；
- 至少 95% 图像的 oracle corner max `<=16 px`；
- 至少 98% 图像的 oracle 满足 `PairLocalReady`。

满足时 plain hard-top1 WLS 无法利用该上限。下一版本必须保留 top8/top16 候选，通过仿射
几何一致性重排后再做 WLS/IRLS。

### G4：可见性和黑边，对应 B3

若 GT-in-bounds 诊断相对全部 anchors 的 `PairLocalReady` 提升至少 20 pp，且 in-bounds
子集满足 G2 或 G3，则下一版本重点实现 dustbin、可见性预测和越界点降权。GT 过滤结果
本身不能作为方法结果。

### G5：资源门槛

与同一 harness、独立进程重测的 E-000 比较，K128 `dense-contract` 必须满足：

- 从未构造 `4096 x 4096`；score 实际增量不超过 8 MiB；
- raw wall-time p50 `<=50 ms`，p95 `<=63 ms`；
- cold 和 warm peak allocated 均 `<=284 MiB`；
- 5 个独立进程 p50 的 CV `<=5%`；
- K64/K128/K256 matching 时间和内存随 K 近似线性，无隐藏 `N^2`。

G5 是进入下一阶段的最低工程门槛。最终竞争目标为 p50 `<=30 ms`、绝对峰值
`250-270 MiB`，后续再通过高效 attention 和轻量 backbone 降低 feature 峰值。

### 决策

```text
G0 失败 -> IMPLEMENTATION_BLOCKED，修复后重跑
G5 失败 -> EFFICIENCY_HOLD，profile 并清除残留旧路径
G1 或 G2 通过 -> 返回方法讨论任务，设计 E-002B/B1
G3 通过 -> 返回方法讨论任务，设计 E-002B/B2
只有 G4 通过 -> 返回方法讨论任务，设计 E-002B/B3
raw 失败但 cosine 通过 -> 记录 norm hubness，在独立 validation 上锁定后续分数
```

只有同时满足以下三项，才把“冻结 checkpoint 特征的直接稀疏检索”判负：

1. raw 和 cosine 均不满足 G2；
2. `R@64,2-cell <50%`，或者超过 10% 图像少于 6 个空间分散可恢复候选；
3. top64 oracle 的 `PairLocalReady <85%`。

此时转入 learned projection/descriptor head。该结论不能写入 `FAILED_METHODS.md` 作为整个
SparseGeo 方法失败。

## 9. 资源测量协议

统一条件：RTX 4090、batch 1、`512 x 512`、FP32、`eval()`、
`torch.inference_mode()`，输入预驻留 GPU。E-000 和 E-002A 使用同一脚本交替启动独立
进程。

每种方法运行 5 个新进程，每进程 20 次 warm-up、200 次正式迭代。每次前后 CUDA
synchronize，同时记录 `perf_counter` wall time 和 CUDA Event。保存全部 raw durations，
报告 mean/p50/p95/std，最终值取 5 个进程 p50 的中位数。

分段报告 feature、anchor、K-to-all、decode、LS、dense render 和 total。分别测
`affine-core` 与生成完整 flow 的 `dense-contract`。

另以独立进程报告 registered weights、active parameters、steady allocated、cold peak、
warm peak、activation delta、peak reserved 和 `nvidia-smi`。reserved 与 nvidia-smi 只作
诊断，不作通过门槛。
