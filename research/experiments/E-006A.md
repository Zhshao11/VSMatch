# E-006A 实验单：区域引导的置信增长稀疏仿射反馈

方法：`M001 v0.9`

状态：`FROZEN_FOR_ENGINEERING`

## 1. 目的

验证“区域结构匹配 -> 多 affine basin -> affine-guided candidate regeneration -> 置信点增长 ->
跨区域 hard rejection -> 最终仿射”能否替代 GDROS dense flow state 和 dense GRU，同时保持全局纠偏
能力与低资源开销。

本实验不是 E-005A 救援调参。E-005A 的固定 K128、单一 weighted LS、soft target expectation 和
自洽型 reliability 已停止。

## 2. 冻结输入

- 使用 official training archive 的 group-isolated `1607/404` train/dev。
- 输入固定为原始 `512x512`，stride-8 feature 固定 `64x64`。
- GDROS backbone、FeatureTransformer 和 checkpoint 全冻结 no-grad。
- raw `truth_flow/*.flo` 是 candidate 标签、region 标签、affine/grid loss 和 AEPE/CMR 的唯一权威。
- `datum` 只用于 archive 完整性/SHA，禁止作为标签或拟合 GT affine。
- OS 424 和未来 external confirm 禁止访问。

## 3. 主结构

### Region Stage

- source/target feature map 都划分为 `8x8` regions，每个 region 为 `8x8` tokens。
- region descriptor = 区域均值、四象限均值、区域坐标编码，经共享 MLP 投影。
- 每个 source region 对 64 个 target regions 计算 cosine，仅保留 top-L=8。
- region scorer 预测 `P(region center endpoint <= 8px)`。
- basin initializer 对每条 retained region edge 预测 B=8 个 basin assignment logits 和 edge confidence。
  每个 basin 用对应 soft weights 对 region centers 执行 normalized FP32 weighted affine solve。basin
  初始化不得使用 GT；少于 3 个非共线有效 region edges 的 basin 标为 invalid。

### Proposal Pool

- source proposals 复用 M256：64 regions x 4 fixed offsets。
- M256 是有限观察网格，不是 active 上限。最终 active 数量由置信和几何验证决定，可为 0..256。
- 每个 source proposal 最终最多贡献一个 target vote。

### Candidate Regeneration

每轮 t=1..4，对 active 与 unresolved proposals 生成候选，合并去重后保留 trace：

- `global_top8`：proposal 对 4096 target tokens 的 exact cosine top8。
- `region_top8`：proposal 只在其 source region 的 top-L target regions 内搜索，取 top8。
- `affine_local`：每个 basin 在 `H_b(p)` 附近 `9x9` token window 搜索，取 top4。

候选可以在训练 loss 中有 soft 辅助项，但最终坐标必须是 hard selected discrete candidate 加局部
offset；禁止以 top-k expectation 作为最终 target coordinate。local offset 以 pixel 为单位，按轴
clip 到 `[-4,4] px`；只对 discrete candidate center 到 raw target point 的距离 `<=8 px` 的候选监督。

### Confidence Growing

- 每轮每个 proposal 属于 `active / unresolved / rejected` 之一。
- candidate confidence 目标是 `P(endpoint error <= 2px)`，不是 `P(agree with current H)`。
- 进入 active 的候选必须同时通过 calibrated confidence、basin score、local evidence 和
  leave-region-out validation。固定阈值为：round 1/2/3/4 的 active confidence `0.90/0.85/0.80/0.75`；
  confidence `<0.40` 且所有 basin leave-out residual `>8 px` 的 proposal 进入 rejected；其余保持
  unresolved。
- unresolved proposal 后续轮次继续用当前 basin 重新生成候选。
- rejected proposal 不参与拟合，但保留 trace 用于审计。
- 不设置人工 Kmax；只设最终有效下限：`>=12` effective inliers、`>=6` source regions、`>=3`
  quadrants、condition `<=20`。

### Cross-Region Robust Solve

- 每个 basin 独立拟合。
- 区域总权重归一化，防止单一区域支配。
- 第一次 robust solve 使用通过 confidence gate 的 active candidates。
- 第二次只校验不扩展：对每个 region r，用排除 r 的 inliers 拟合 `H_b^{-r}`，再用该 affine 验证
  region r 的 candidates；residual 超过 `2.5 px` 或 confidence 低于本轮 active 阈值者 hard reject。
- final affine 使用 surviving inliers 重拟合一次；不再执行第三轮扩展。
- 最终从 B=8 basins 中选 score 最高且满足有效条件的 affine；若无 basin 满足则 explicit abstention。

## 4. 损失

- region BCE：region center endpoint `<=8px`。
- candidate BCE：candidate endpoint `<=2px`。
- local offset loss：只对 GT-nearest candidate 半径内样本监督。
- basin grid loss：每轮 `16x16` grid，bilinear 读 raw flow，`align_corners=true`，zero padding。
- confidence calibration：Brier 或 ECE surrogate，目标为最终 affine grid error `<=5px`。
- hard rejection 辅助 loss：false-positive active candidates 加权惩罚。
- 所有创新模块必须有有限非零梯度，并通过 toy overfit。

## 5. 自动验证

必须覆盖：

- 坐标方向 `optical -> SAR`、flow 为 `target-source`。
- region top-L、candidate 来源、candidate 数量和去重 trace。
- no hidden `4096x4096` correlation、no dense flow state、no dense GRU。
- no GT/datum/OS424/confirm in inference path。
- active/unresolved/rejected 状态迁移。
- no artificial K128/Kmax clamp。
- leave-region-out validation 确实排除本 region。
- region-balanced weight normalization。
- full-image no-mask AEPE/CMR metric parity。
- checkpoint save/load、gradient、toy overfit。

## 6. Gates

P0 capacity and budget gate，失败则不训练：

- P0 oracle 允许使用 raw flow 选择正确 target region、正确 basin 和正确 candidate，仅用于证明
  候选再生成空间有上限；oracle 选择和 GT affine 不得写入训练、G1、G2 或 checkpoint。
- candidate-regeneration GT oracle dev AEPE `<=1.6 px`。
- oracle PairLocalReady `>=99%`。
- mean 2px GT-correct proposal count `>=140/256`。
- 至少 `99%` pairs 满足 `>=12` inliers、`>=6` regions、`>=3` quadrants、condition `<=20`。
- 静态 trace 证明 score elements 不超过冻结公式，且无 hidden N2。

G0 implementation gate：

- 自动测试 PASS。
- 创新契约 reviewer APPROVE。
- 训练协议、provenance、许可证和 split 隔离 PASS。

G1 dev accuracy gate：

- main seed dev AEPE `<=max(2.0 px, dense-GDROS-dev + 0.35 px)`。
- CMR@2 相对 dense-GDROS-dev 下降不超过 `3 pp`。
- PairLocalReady `>=99%`。
- final GT 2px inlier ratio `>=65%`。
- self-consensus 与 GT inlier gap `<=20 pp`。
- mean active count、P10/P50/P90 active count 必须报告；不得因点数过多事后加 cap。
- second seed 同方向，不能替换 main seed。

G2 resource gate：

- core p50/p95 `<=20/30 ms`。
- slim end-to-end p50/p95 `<=35/50 ms`。
- 相对同进程 GDROS p50 speedup `>=2.5x`。
- warm allocated `<=284 MiB`。
- 必须报告 active count 与耗时/显存关系。

任一 gate 失败，写 `RESULT_CARD.md` 后停止。不得自动创建 E-006B、descriptor 微调、扩大 proposal
grid、调阈值救援或恢复 dense GRU。

## 7. 消融

- dense GDROS frozen dev baseline。
- E-005A checkpoint/result-card reference。
- no region stage：只用 global_top8 + affine_local。
- single basin B1。
- no affine-guided regeneration。
- no leave-region-out validation。
- no hard rejection，只用 weighted LS。
- fixed K128 compatibility ablation，仅作诊断，不作为主方法。
