## 1. 决策与研究边界

E-002B 的正式 G5-R 已证明当前固定 Python/PyTorch 穷举后端不具备资源资格：B2
p50/p95 为 `888.752/911.972 ms`，baseline 为 `76.189/82.349 ms`。但其 424-pair
accuracy 因硬前置失败而没有运行，所以不能判断 B2 candidate selector 的精度。

本实验只回答：在完全保持 E-002B 方法语义时，能否通过向量化、融合或编译后端把几何
reranker 降到资源门槛内。先减少 T/Q/R 或自适应剪枝会同时改变方法预算和实现，导致后续
精度变化不可归因，因此不进入本版。

本实验是工程救援，不单独主张论文创新；E-002A 的 G1-G5 FAIL 与 E-002B 的 G5-R FAIL
均为历史事实，不得追认或覆盖。

## 2. 冻结的语义合同

optimized backend 必须与 E-002B v0.4 reference 保持以下内容不变：

1. 同一 released checkpoint、slim feature path、optical source/SAR target、stride-8 坐标和
   `target-source` flow 方向。
2. K128 public-stratified anchor map 和 anchor SHA256
   `2872a818932f138d79a0a0aebf3fec2bbadb1939e839788f6f103c1e1f16efb6`。
3. C8-main 使用 cosine top8，候选按 score 降序、target row-major index 升序稳定排序。
4. 相同 ordered 256-triple bank、相同 rank combination 顺序和 hypothesis ID：
   `id = bank_index * 512 + rank_combination_index`。必须尝试全部 131,072 个 ID；target 重复、
   共线和 nonfinite 的有效性判断与计数完全相同。
5. 相同 FP32 归一化、仿射方向和矩阵共轭；不得启用 TF32、FP16、BF16 或近似求解来换取
   等价门槛中的速度。
6. 相同 32 sentinels、BIND-001 唯一-target survivor 规则和六级字典序键；collision 被抑制
   source 在 key 4/5 中仍贡献 cost `4` 和 rank `L`。
7. 相同 coarse `Q=1024`、full `R=32`、完整 K128 重排、两轮 candidate reassignment +
   ordinary LS，以及第二轮后只校验、不做第三次拟合的 final validation。
8. 相同 `L_inf<=1/2` 阈值、至少 12 对应、至少 3 象限、rank 3、condition `<=20`、
   abstention 和 identity dense-contract 语义。
9. 正式 accuracy 仍包含 E-002B 预注册的 C8-main、C8-consensus-only、C8-C16-diagnostic、
   R8-diagnostic；只有 C8-main 是资源与方法主结果。
10. 全部正式路径不使用 GT、valid mask、black-border filter、baseline flow 或测试标签。

E-002B v0.4 reference 绑定：Git
`ee6b6216fe780bc03bfb4759ae094daa0cfddc60`，implementation manifest
`3dd002c8f92c4ac58571ba04b92cbda6830843bce9662d93dd5d5ab67f35e58c`，正式 source snapshot
位于 E-002B run-01 的 `g5r/source_snapshot`。不得用正在修改的 optimized 模块同时充当
reference。

## 3. 允许与禁止的后端变化

允许：

- 缓存与图像无关的 rank combinations、source inverse、normalization 和 bank tensors；
- 将多个 triple/rank combination 批量生成，删除 512 次 Python chunk 驱动；
- 按固定 implementation block 对 hypothesis generation、validity 和 sentinel scoring 融合；
- 使用向量化 PyTorch、`torch.compile`、Triton 或自定义 CUDA extension；
- 用确定性的 segment/scatter/sort 实现唯一-target winner，避免不必要的 pairwise collision
  tensor；
- 一次保留全部 hypothesis matrix/key 或使用确定性分块 top-Q，只要不生成完整
  `H x K x L` residual cube且满足显存门槛；
- 批量执行 32 个 assignment、ordinary LS 和 final validation；若批量线性代数不能通过
  数值等价门槛，则该小段保留 reference 实现；
- implementation block 可在 synthetic 输入上从 `{1024,2048,4096,8192,16384}` 中仅按
  延迟和显存选择一次，记录选择规则和结果，并在读取第 4 节的 10 对官方 parity 输入前
  锁定；不得查看 OS accuracy 后再改。

禁止：

- 丢弃、抽样、提前终止或按图像自适应减少 hypothesis；
- 改变 T、L、Q、R、sentinel、阈值、排序键或 tie-break；
- approximate top-k、近似最近候选、量化或混合精度；
- 新增旋转/尺度/平移/行列式/in-bounds 先验；
- WLS、IRLS、learned descriptor、B1/B3、局部精修、温度或 score 变更；
- 以编译时间、异步未同步时间或缓存其他 pair 的结果隐藏实际推理成本。

## 4. P0-early：后端等价门槛

任何资源结论前，reference 与 optimized 必须在相同输入和 CUDA 数值设置下通过：

1. 现有 100 个固定 synthetic cases，外加 collision、equal residual、equal candidate score、
   duplicate target、collinear target、round1/round2/final-validation invalid 和 abstention
   边界单测。
2. E-002B 已归档的 2-pair smoke。
3. 以 E-002B 正式 official evaluation manifest 的固定评测顺序为准，使用 zero-based 索引
   `[0,47,94,141,188,235,282,329,376,423]` 的 10 对固定输入；本项不读取 GT、不计算
   AEPE/CMR，只比较 non-GT execution trace。
4. C8-main 必须在全部上述输入上比较；C8-consensus-only、C8-C16-diagnostic 和
   R8-diagnostic 也必须在 2-pair smoke 与固定 10 对官方输入上分别通过同一 P0-early 规则，才可
   进入相应 variant 的正式 accuracy。
5. 每种输入固定导出 reference 与 optimized 的 candidate index/score、有效 hypothesis ID/skip
   计数、coarse top1024、full top32、两轮 assignment、final validation 和最终输出。

必须精确相等的离散量：

- candidate index/rank、accepted hypothesis ID 升序序列和四类生成计数；candidate score
  max-abs `<=2e-5`；
- coarse top1024 与 full top32 的 hypothesis ID 及顺序；
- integer consensus keys、assignment target index/rank、unique/survivor mask；
- 每轮 valid/abstention、对应数、象限数、rank、failure reason、最终 hypothesis ID。

浮点量固定容差：

- 生成 hypothesis normalized/lattice matrix max-abs `<=2e-6`；
- coarse/full truncated-cost max-abs 分别 `<=2e-4/1e-3`，且不得改变上述排序；
- 两轮 assignment/final-validation residual max-abs `<=2e-5`，finite condition relative
  difference `<=1e-4`；
- 最终 normalized/lattice matrix max-abs `<=2e-5`，pixel matrix max-abs `<=2e-4`；
- 最终 dense flow max-abs `<=1e-2 px`。

容差只用于浮点实现差异，不能对排序或 valid/abstention 差异做 near-tie 豁免。P0-early 任一项
失败即为 `IMPLEMENTATION_BLOCKED`，必须修复并重新由独立子 agent 审阅；不得运行 P1、
G5-R2、P0-full 或 accuracy。

## 5. P1：单进程救援可行性

P0-early 通过后，在一张 RTX 4090、batch 1、512x512、FP32、eval/inference、输入预驻留 GPU
下做开发阶段 microbenchmark：reference 与 optimized 分别使用独立 fresh process，采用
相同输入和条件；每个进程 20 warm-up、200 measured，每次 CUDA synchronize，保存 raw
wall/CUDA Event 数据。

- optimized geometry reranker p50 `<=80 ms`；
- 相对同次 v0.4 reference geometry p50 加速 `>=8x`；
- warm peak allocated `<=284 MiB`；
- 计时完成后在计时区间外复验输出仍通过 P0-early trace checker。

P1 只用于避免在明显不够快的后端上投入正式五进程审计，不解除 hold。P1 失败时停止并返回
方法任务；不得通过降低 hypothesis 预算补救本实验。

## 6. G5-R2：正式资源资格

P0-early/P1 和独立代码审阅通过后，使用 watchdog 运行正式资源审计：

1. RTX 4090、batch 1、512x512、FP32、eval/inference、输入预驻留 GPU。
2. optimized C8-main dense-contract 与未修改 baseline 各 5 个 fresh process；每进程
   20 warm-up、200 measured，每次 CUDA synchronize，不得剔除进程。
3. 每个进程分别从自己的 200 条未插桩端到端 wall timing 计算 p50/p95；正式 p50/p95 是
   五个进程各自 p50/p95 的中位数，门槛分别为 `<=50/63 ms`。CV 由五个进程 p50 计算，
   门槛 `<=5%`。不得合并 1,000 条 timing 后重算 gate，也不得把同步分段耗时相加代替
   未插桩总延迟。
4. cold/warm peak allocated 均 `<=284 MiB`；另报告 reserved memory、进程 RSS、首次编译或
   extension load 时间与一次性缓存大小。编译时间不计入 warm inference，但必须单列，且
   编译后推理不得依赖前一 image pair 的特征或结果。
5. K128 cross-image score 必须严格为 `128 x 4096`，score incremental peak `<=8 MiB`；
   不存在 `4096 x 4096` cross-image correlation、完整 `H x K x L` residual cube或被重新
   启用的 CorrBlock/context/GRU/upsampler/cost-perceiver。
6. candidate matching core 单独使用 K=`64,128,256,512,1024`、预驻留 contiguous feature、
   至少 100 inner repeats 放大信号；score count 精确线性、incremental peak memory R2
   `>=0.99`、timing 正斜率且 R2 `>=0.90`。geometry 只定义于冻结 K128，不混入该 K-scaling
   回归，也不得用该子系统回归替代第 3 项端到端绝对延迟。
7. 报告 feature、candidate、hypothesis+coarse、full consensus、两轮 refit/final validation、
   render 的未插桩总计与同步 diagnostic；报告 attempted/accepted/skips、吞吐和 live shapes。
8. 同一次审计保存 v0.4 reference timing，作为工程归因对照，但 gate 只按 optimized 绝对
   门槛和 baseline parity 判定。

G5-R2 必须全部通过才可进入 P0-full；只有 P0-full 也通过才解除 `EFFICIENCY_HOLD` 并
启动正式 accuracy。程序成功退出不等于 gate PASS。

## 7. P0-full：424 对无 GT 全轨迹等价

G5-R2 通过后、读取任何 GT 或计算 accuracy 前，reference 与 optimized 必须在官方全部
424 对上完成一次无 GT 等价审计：

1. evaluation loader 不打开 GT 文件，方法调用链不接收 GT tensor、valid mask、baseline
   flow 或测试指标；GT 隔离用 non-GT trace hash 前后不变测试复核。
2. 对 C8-main、C8-consensus-only、C8-C16-diagnostic、R8-diagnostic 四个预注册 variant
   逐对应用第 4 节的离散精确等价与浮点容差，不允许只比较最终 affine 或 aggregate。
3. 保存 424 对 reference/optimized trace manifest、逐 pair/variant checker 结果、文件 SHA 和
   总结；要求 `424 x 4` 全部 PASS，不设 near-tie 或失败率豁免。
4. P0-full 使用 watchdog，可与 accuracy 复用已锁定的 source build 和数据 manifest，但必须
   使用独立输出目录，且 accuracy 只能在 P0-full checker 已正式 PASS 后启动。

P0-full 任一差异均为 `IMPLEMENTATION_BLOCKED`，先定位并修复 optimized backend，再重新从
受影响的等价与资源 gate 开始；不能把差异解释为方法精度变化。

## 8. Accuracy 与后续决策

只有 P0-early、P1、G5-R2、P0-full 全部通过，才可在官方 424 对上补跑 E-002B v0.4 已预注册 accuracy。
数据、checkpoint、variant、指标、bootstrap、报告项和主门槛完全沿用 `E-002B.md` 第 10、
11 节，禁止依据本轮 10 对无 GT parity 输入或正式 424 对结果改变配置。

```text
P0-early FAIL
  -> IMPLEMENTATION_BLOCKED；修复等价性，不能解释方法

P0-early PASS, P1 或 G5-R2 FAIL
  -> COMPLETED / EFFICIENCY_HOLD；只否定等价后端救援的资源资格
  -> 不运行 accuracy，不进入 E-002C，不自动减少预算

P0-full FAIL
  -> IMPLEMENTATION_BLOCKED；修复全数据等价性，不计算 accuracy

P0-early/P1/G5-R2/P0-full PASS, C8-main accuracy 主门槛 PASS
  -> B2-bridge 精度与资源可行；返回方法任务决定 E-002C

资源 PASS 但 accuracy FAIL
  -> 审计 selector/oracle gap；返回方法任务决定预算化 B2、其他冻结分支或 descriptor
```

即使 E-002B-R 资源失败，也不写 `FAILED_METHODS.md`：它否定的是等价工程后端能否在当前
门槛内执行，不是候选选择精度。只有后续改变预算并完成独立精度审计，才可能对 B2 方法
本身作更强结论。
