## 固定问题与四组输出

| ID | 路径 | 目的 |
|---|---|---|
| B | 当前 M4 的 B 子模块输出 → 官方 LSR | 完整 B 单支 |
| C | 当前 M4 的 C.student 输出 → 官方 LSR | 蒸馏 student 单支 |
| AVG | 0.5×B 原始 flow + 0.5×C.student 原始 flow → 官方 LSR | 固定平均 |
| M4 | 当前已训练区域 gate 融合 B/C 原始 flow → 官方 LSR | 完整预测依赖路径 |

禁止将缺失分支置零后继续套用旧 gate；B/C 两个单支直接输出，不存在给旧外层
gate 输入替代分布的操作。AVG 先融合再末端拟合，不能默换成两个 post-LSR
预测的平均。B 内部门控及其 LSR 保持原样。

主表固定 32 轮，24 轮为预声明精度补充；以 32 轮独立部署路径为性能主表。

### teacher 冗余与等价验证

当前 C.forward 即使 eval 也计算 teacher F2/F3，但只返回 student；M4 原实现因此
含两个不影响最终预测的 teacher。性能主表应使用明确的有效部署路径：
C 仅加载 student；AVG/M4 使用 B、C.student 和各自需要的融合运算。
不得在 C 单支计时中仍运行 teacher，再据此判定 C 无轻量化价值。

先对固定无GT选择的 8 个 pair index `0,60,120,180,240,300,360,423`：

1. 严格核验有效参数；比较原 C 返回值与 C.student。
2. 比较原 B 与独立 B；原 M4 与仅剥离无返回值依赖 teacher 的部署 wrapper。
3. 比较 24/32 轮的 raw flow 和末端 LSR 结果，报告 max/mean abs diff。
4. 优先要求逐位一致。若出现非零差异，先调查模型状态、随机性、后端及调用路径，
   不因测试分数接近就放行。精度等价上限预先设为 raw max<=1e-5、post max<=1e-4；
   若超过则修复或保留原路径，禁止事后放宽。

另保留原完整 M4 的延迟/显存作为实现参考附行，明确它包含冗余 teacher。
四组主表不得让 M4 含冗余而 C 不含冗余，却把差距全部归因为双支架构。
原路径与有效部署 wrapper 的数字始终分列，源文件/参数及 parity 都要留证。

## 精度评测

可共享一次原模型或已验证 wrapper 的 B/C 原始序列来构造四组输出，以节省GPU；
每组必须先独立物化全部424对最终预测及哈希 manifest，再做独立CPU GT join。
推理及性能阶段均不加载GT，GT不影响择支、门控、轮数或样例选择。
E092A M4预测如资产身份和哈希完全一致，可作为回归参照，不能只核对旧标量。

双口径分表：公开分量误差 mean((|dx|+|dy|)/2)，标准二维向量 EPE。
全图含黑边无mask，先每对均值再跨对；CMR严格 `<t`。
每组报告均值、CMR@1/2/3/4/5/10/16、>=5失败数、P95/P99、方差及真实标准差。
如需成功子集 AEPE/variance，注明条件子集及公式，不把 np.var 称为真正RMSE。
补充各阈值1/2/5的B/C成功交叉表、逐对胜负和误差差值。
原424对已被多次观察，结果属于探索性固定模型贡献诊断，不宣称新的未见测试证据。

## 推理耗时与显存：必须独立部署测量

共享精度预测的计时不能作为四个独立部署模型的延迟。分别以新进程/干净CUDA状态
加载 B、C student、AVG、有效 M4；模型驻留时仅保留该路径需要的模型组件。
禁止四个模型全部常驻后把相同基础显存当作各单支成本。
不随意裁剪 matcher 内部注册模块；只剥离已验证的 C teacher 路径。

统一 GPU、精度、batch、输入和后端配置，通过独占 watchdog 分配，不干扰他人。
若其他进程/显存占用、温度或限频使计时不可信，记录并等待可比窗口，不强行出排名。
先完成/验证精度路径，再序列化各性能任务，避免与本实验其他GPU任务竞争同卡。

- 固定64对：`floor(k*423/63)`，k=0..63，均匀覆盖完整列表，无GT筛选。
- 每个变体先10次预热；64对固定顺序，完整测3轮，共192个样本计时。
  若运行预算允许扩大样本可追加，但首个协议结果保留，不替换。
- 输入在GPU且预加载，主计时不含磁盘读取、图像解码、H2D输入拷贝、预测落盘、GT join。
  把主计时称为“模型计算延迟”，不要称包含I/O的端到端应用延迟。
- 主延迟用 `perf_counter` 且起止 CUDA synchronize，覆盖该部署路径全部前向和末端LSR，
  包括原实现内部的CPU传输/同步开销。CUDA events可另列，不能用它掩盖CPU等待成本。
- 输出预先明确为最终预测 CPU float32 张量，与官方LSR返回一致。
  每对预测在测量后释放；不得跨样本保存GPU张量或把评测归档计入计时。
- 可拆分网络前向（含内部LSR）、末端LSR、完整计算路径；拆分测量可能额外同步，
  完整主延迟必须单独计时，不用拆分数值硬凑。
- 显存报告模型加载后 allocated/reserved 基线、预热后稳态基线、
  `max_memory_allocated` / `max_memory_reserved` 的绝对峰值和相对稳态基线增量。
  预热后在同步状态 reset_peak_memory_stats；192对测量期间不逐样本 empty_cache。
  加载/初始化峰值另列，不能混成稳态推理峰值。
- 记录 GPU型号/UUID/总显存、其他进程、利用率/温度/功耗/频率可得快照，
  CUDA/PyTorch/驱动、计时入口源码SHA、实际可训练/注册参数计数（如提供，区分其含义）。
- 逐对/逐重复记录耗时，汇总median、mean、P95、std和样本数；均报告ms/对和MiB。
  `nvidia-smi`整体显存可作辅助快照，不能代替PyTorch峰值统计。
