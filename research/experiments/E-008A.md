# E-008A 实验单：Region-to-Point Cross-modal Candidate Generator

方法：`M001 v1.1`

状态：`USER_APPROVED / FROZEN_FOR_ENGINEERING`

## 1. 目的

设计并验证一个新的候选生成器，超过冻结旧方案 `E-006A corrected candidate generator`。

本实验不再在旧候选集上继续捞点或堆 verifier。核心问题是：能否通过区域到点的跨模态生成过程，
让正确候选更多且更可分。

旧方案冻结指标见 `research/CANDIDATE_GENERATION_BASELINE.md`。

## 2. 冻结输入与禁止项

- 数据：official training archive，group-isolated `1607/404` train/dev。
- 输入：原始 `512x512` optical/SAR；raw truth_flow 是训练标签和指标唯一权威。
- GDROS checkpoint 可用于冻结特征；若训练新 descriptor/adapter，GDROS backbone/FeatureTransformer
  仍默认 frozen no-grad，除非方法任务另行批准。
- OS424、external confirm、datum labels、旧 invalid `p0-gate.json` 禁止访问。
- 禁止 dense flow hidden state、dense GRU、hidden full `4096x4096` cross-image tensor、RANSAC、
  IRLS、三点 hypothesis enumeration、baseline fallback、跨样本缓存。

## 3. 新候选生成器

### 3.1 Multi-scale Region Matching

- source/target region scales：`4x4`、`8x8`、`16x16`。
- 每个 region descriptor 来自 raw intensity、structure channels、frozen GDROS feature summary 和
  optional trainable region adapter。
- 每个 source region 保留 top-L target regions：
  - `4x4`: top4
  - `8x8`: top8
  - `16x16`: top8
- region matching 只定义搜索范围和 coarse hypotheses，不直接作为最终点匹配。

### 3.2 Dynamic Source Proposal Generation

- source proposals 不固定为 M256。
- 每个 region 有保底 proposals：`4x4` 每区 2，`8x8` 每区 1，`16x16` 每区可选 0。
- proposal score 来自 source-side corner/edge/structure saliency、region match confidence 和 local
  feature distinctiveness。
- 不设人工上限；但必须报告 proposal count P10/P50/P90、最大值和资源。若实现需要 batch padding，
  padding 不得改变语义。
- proposal generation 不得使用 GT、datum、OS424 或 confirm。

### 3.3 Region-guided Local Dense-lite Search

- 对每个 selected source proposal，只在 matched target regions 内做 dense-lite local search。
- target search tokens 为 region union 后的 token set；禁止全图 `4096` blind search 作为主路径。
- 每个 source proposal 输出 top candidates，候选数按来源报告：
  - region descriptor top candidates；
  - local patch/structure verifier candidates；
  - descriptor adapter candidates。
- local descriptor/patch score 参与候选生成排序，不再只是旧候选集 verifier。
- 保留 hard discrete target candidate 和 score；不以 soft expectation 作为候选坐标。

### 3.4 Candidate Dedup And Trace

- 同一 source proposal 的 target candidates 按 target token/local offset 去重。
- 同一 source proposal 最多贡献一个 final selected candidate；候选生成评估仍统计所有 generated
  candidates 的 label base rate。
- 必须保存每条候选的 source proposal id、region scale、target region id、candidate source type、
  score、rank、target coordinate 和 no-GT trace。

## 4. 训练

- 允许训练 region adapter、proposal scorer、patch/structure verifier 和 local descriptor adapter。
- 训练只用 train split raw flow 标签。
- positives：candidate endpoint `<=2 px`。
- hard negatives：同 source proposal 内高分错误 target、同 matched region 错误 target、邻近 basin
  错误 target。
- 必须包含 toy overfit、梯度到所有创新模块、checkpoint save/load。
- dev 只用于正式评估和早停指标；不得用 OS424/confirm。

## 5. 对照

主对照为 `E-006A corrected candidate generator`：

- mean 2px-correct proposals：`66.210/256`
- P10/P50/P90：`33/64/98`
- 2px candidate base rate：`0.1343%`
- P@32：`2.259%`
- AP：`0.01386`
- best observed selector affine AEPE：`36.0761 px`
- oracle affine AEPE：`0.190768 px`

E-008A 必须在同一 404 dev split 上重算旧方案 parity 或读取冻结 baseline card 并校验 SHA。

## 6. 评价指标

### Candidate Coverage

- generated source proposal count P10/P50/P90/max；
- generated candidate count per pair；
- 2px-correct proposal count mean/P10/P50/P90；
- 1/2/5px candidate base rate；
- in-bounds rate；
- candidate source type 分组。

### Candidate Selectability

- candidate AUROC/AP/ECE；
- topK precision/recall for K `{16,32,64}`；
- P@32 primary；
- learned selector 可以复用 <=100k pointwise scorer 或 E-007A all-evidence style fusion，但必须只作用于
  新候选集。

### Affine Upper And Practical Fit

- GT hard 2px inlier oracle affine AEPE；
- GT-nearest per-proposal oracle affine AEPE；
- no-GT topK-32 affine AEPE、CMR@2/5、PLR、valid；
- full-image no-mask metric。

### Resource

- candidate generation p50/p95；
- descriptor/patch scoring p50/p95；
- selector p50/p95；
- peak allocated memory；
- train time and train peak memory for any trained module。

## 7. Gate

P0 candidate generation gate：

- mean 2px-correct proposals `>66.210` and P50 `>64` and P10 `>33`；
- 2px candidate base rate `>0.1343%`；
- oracle affine AEPE `<=0.5 px`；
- PairLocalReady/valid `>=99%`；
- no hidden N2/dense GRU/GT leakage。

P1 useful candidate gate：

- P@32 `>2.259%` and AP `>0.01386`；
- no-GT topK-32 affine AEPE `<36.0761 px`；
- CMR@2 `>0%`。

Suggested success target，不作为硬失败唯一依据：

- mean 2px-correct proposals `>=100`；
- P50 `>=96`；
- P10 `>=64`；
- 2px base rate `>=0.5%`；
- P@32 `>=10%`；
- AP `>=0.05`；
- no-GT affine AEPE `<=5 px`。

若 P0 失败，不进入 P1。若 P1 失败，写结果卡后停止。通过 P0/P1 也只写结果卡，等待方法任务和
用户决定是否进入完整 sparse affine feedback。
