# E-013A：Geometry-supervised Learned Inlier-Basin Scorer

## 目的

E-013A 检验：

> 能否把 E-012A 失败的 geometry-only 规则，改成训练时由 endpoint/affine 几何监督驱动的 learned
> inlier-basin scorer，在推理无 GT 的条件下从 E-011A top128 中选出高纯动态 sparse matches？

本实验只训练 top128 candidate purification 和 basin scoring，不重训 descriptor，不启动完整 sparse affine feedback。

## 输入与隔离

- 输入：E-011A formal train/dev top128 candidate outputs，只读。
- 标签：official training archive 的 raw `truth_flow`，仅用于 train/dev label、loss 和评测。
- split：沿用 group-isolated `1607/404` train/dev。
- 禁止：datum、OS424、confirm、测试集 GT、跨样本缓存。
- GDROS baseline 与 E-011A retriever/checkpoint/cache/result 全部只读。
- E-013A 新代码、cache、checkpoint、日志、结果必须位于独立 `e013a` / `E-013A` 路径。

## 关键语义

- 训练时可以使用 raw truth_flow 生成 endpoint labels、basin labels、affine loss。
- 正式 inference、阈值选择、basin 初始化、candidate compression 不得读取 truth_flow 或 oracle labels。
- `top128` 是每个 source proposal 的 target candidate depth，不是最终点数上限。
- 最终 active set 动态决定；每个 source 最多一个 target；不可靠 source 进入 dustbin/pending/rejected。

## 标签构造

### Endpoint labels

对每个 candidate：

- hard positive：candidate target 到 raw truth_flow endpoint 的 Euclidean error `<=2 px`；
- hard negative：error `>5 px`；
- ignore/soft：`2<error<=5 px` 可用于 soft Gaussian auxiliary；
- soft target：`exp(-d^2 / sigma^2)`，默认 `sigma=4 px`，需记录。

### Basin labels

在 train split 内构造，不用于 inference：

- 用 hard positives 或 GT endpoint 对当前 pair 生成 oracle affine；
- residual 到 oracle affine `<=2 px` 且 endpoint positive 的 candidate 标为 basin inlier；
- residual 大且 endpoint negative 的 candidate 标为 basin outlier；
- 若一个 pair 的 hard positives 不足以生成稳定 affine，则只使用 endpoint loss，不使用 basin/affine loss，并报告比例。

### Affine supervision

每轮 weighted affine 输出在 16x16 grid 或 512x512 sampled grid 上与 raw truth_flow 计算 EPE loss。
采样协议必须固定并记录。

## 模型

实现 `GeometrySupervisedInlierBasinScorer`：

1. 读取 E-011A top128 candidates：source xy、target xy、rank、score、source id、region、scale、patch/descriptor evidence。
2. 构造 feature：rank/score、source/target xy、displacement、region/quadrant、target duplicate/local density、
   current residual、coverage contribution、condition proxy、basin id。
3. `B` 个 basin slots，默认 `B=4`；`T` 轮，默认 `T=3`。
4. 每轮：
   - candidate inlier/dustbin/pending logits；
   - basin assignment logits；
   - one-source-one-target selection；
   - FP32 weighted affine solve；
   - residual feedback features；
   - rescore。
5. 输出 best basin dynamic active matches、affine matrix 和解析 affine flow；若无合法 basin，显式 abstain。

## Loss

总 loss 至少包含：

- endpoint focal/BCE loss；
- soft endpoint regression/listwise loss；
- basin assignment loss；
- affine EPE loss；
- precision/coverage/condition regularizer；
- dustbin/pending/rejected state loss。

必须报告各 loss 权重、是否非零、梯度是否到 scorer/basin heads。

## 禁止实现

- dev/test inference 读取 truth_flow、datum、OS424、confirm 或 oracle labels；
- 训练或微调 GDROS backbone/FeatureTransformer/E-011A descriptor；
- 修改 GDROS baseline 或 E-011A 源码、checkpoint、cache、results；
- E-012A deterministic geometry rule 作为 fallback；
- 固定最终 K64/K128；
- 三点 RANSAC、穷举 affine hypotheses、131,072 hypotheses；
- dense flow state、dense GRU、hidden `4096x4096` cross-image tensor；
- full-image blind target search；
- 自动启动 E-013B、descriptor 重训、完整 sparse affine feedback 或 rescue。

## Gate

### G0：协议、训练与实现

- E-011A top128 parity PASS。
- GDROS/E-011A read-only isolation PASS。
- label construction audit PASS：labels 只由 train/dev raw truth_flow 生成，datum/OS424/confirm 未使用。
- candidate outputs before label join PASS。
- no GT inference trace PASS。
- gradient/loss participation PASS：endpoint、basin、affine、precision/coverage loss 非零且梯度到 scorer/basin heads。
- toy synthetic recovery或过拟合 PASS。
- one-source-one-target、dynamic active size、coordinate direction、weighted affine tests PASS。
- no hidden N2、no RANSAC/131k tests PASS。
- 至少一名定向 reviewer APPROVE。

G0 FAIL 时停止，状态 `COMPLETED / PROTOCOL_OR_TRAINING_FAIL`。

### G1：candidate purification

dev404 上必须同时满足：

- active precision mean `>=20%`，P10 `>=5%`，P50 `>=15%`；
- correct@2px active count mean `>=24`，P10 `>=8`，P50 `>=20`；
- active matched source count mean `>=32`，P10 `>=12`；
- 覆盖至少 3 quadrants 且至少 6 个 8x8 regions 的 pair 比例 `>=90%`。

G1 FAIL 时停止，状态 `COMPLETED / LEARNED_PURIFICATION_FAIL`，不得运行 G2 或救援。

### G2：无 GT affine 资格

仅 G1 PASS 后运行：

- AEPE `<=2.0 px`；
- CMR@2 `>=60%`，CMR@5 `>=90%`；
- PairLocalReady/valid `>=95%`；
- condition pass pair ratio `>=95%`；
- eval p50/p95、峰值显存、live score elements 必须报告，且无 hidden N2。

G2 FAIL 时停止，状态 `COMPLETED / AFFINE_QUALITY_OR_RESOURCE_FAIL`。

G2 PASS 时状态 `COMPLETED / LEARNED_GEOMETRY_PURIFICATION_READY`，等待用户决定是否进入完整 sparse affine feedback。

## 诊断

报告但不追认：

- no-geometry-supervision；
- no-appearance-evidence；
- endpoint-only；
- no-affine-loss；
- single-round vs multi-round；
- single-basin vs multi-basin；
- threshold/active count/precision/AEPE 曲线；
- oracle gap 到 all-hard2px compression oracle；
- failure buckets：label imbalance、appearance confusion、basin confusion、coverage/condition、candidate noise。
