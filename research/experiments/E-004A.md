# E-004A：覆盖约束的自适应 Anchor 预算与候补替换

方法：`M001 v0.7`

状态：`READY`

## 1. 研究问题与边界

验证固定 K128 是否可被有最坏预算约束的动态 anchor acquisition 改善：先以粗跨模态响应从
M256 proposal 中分区选择 K128 primary，再用 fine-search 质量对最多 R64 个 primary 做同区域
单轮 reserve replacement。

本实验只评价 source anchor acquisition。正式仿射指标使用 GT-nearest top8 target oracle，不能
作为可部署匹配精度。不得加入 RG-SAC、新 candidate selector、descriptor 训练或局部精修。

## 2. 数据与冻结前端

- 复用 E-003A training archive、`1,607/404` group-isolated train/dev manifest 和全部 SHA。
- official `512x512` 原图；不 resize/crop/flip/FlowAugmentor。
- 冻结官方 GDROS checkpoint、post-Transformer stride-8 `64x64` 特征，全部 no-grad。
- optical 为 source，SAR 为 target，flow 为 `target-source`。
- raw truth_flow 是训练标签和 oracle 诊断的唯一权威；datum 不作标签。
- OS 424 与未来 external confirm 在所有 E-004A 进程中禁止访问。

## 3. 确定性 Proposal Pool

将 source `64x64` token map 划分为 `8x8` 个区域；region `(ry,rx)` 覆盖 token
`y in [8ry,8ry+7]`、`x in [8rx,8rx+7]`。每区 proposal offset 固定为
`(dy,dx) in {(2,2),(2,6),(6,2),(6,6)}`，按 `(ry,rx,dy,dx)` 排序，共 M256 unique tokens。

每个 proposal 的 GT recoverable 标签只在训练和诊断生成：在 source pixel `(8xf,8yf)` 读取 raw
truth_flow；GT target 越界或 cosine top8 中最近候选距 GT target 超过 2 stride-8 tokens时为 0，
否则为 1。top8、距离、越界和 tie-break 完全复用 E-003A。

## 4. Coarse Probe 与 Pre-search Head

SAR `64x64` 特征以 `avg_pool2d(kernel=4,stride=4)` 得到 `16x16`，逐 token L2 normalize。
M256 source proposals 同样 L2 normalize，分块计算精确 `256x256` cosine；禁止 source-all x
target-all correlation。

每个 proposal 的无 GT pre-search 特征固定为：source log-norm、source 3x3 邻域内最大/平均
cosine distinctiveness、归一化 source xy、256 个 coarse scores 的 top1、top1-top2 margin、
softmax(score/0.1) entropy、top4 probability mass 和 coarse top1 xy。

source distinctiveness 对中心 token 与图内 8-neighbor 分别做 cosine，记录 `1-max_cosine` 和
`1-mean_cosine`；边界只使用实际存在的 neighbor。coarse top1 cell `(xc,yc)` 映射回 stride-8
连续坐标 `(4xc+1.5,4yc+1.5)`；score tie 使用扁平 target index 最小者。

`PreSearchRecoverabilityHead` 固定为 `Linear(d,32)-GELU-Linear(32,32)-GELU-Linear(32,1)`，
输出一个 logit，参数量单独报告。
使用 train split 全部 M256 标签训练 class-balanced BCE；`pos_weight=N_negative/N_positive` 只由
train manifest 计算并冻结。dev 不参与权重、阈值或结构选择。

## 5. 覆盖约束 K128 分配

每对图像按 pre probability 降序，tie 依次为 `(region_id,proposal_id)`：

1. 每个区域先选该区最高分 proposal，严格得到 64 个 primary。
2. 在所有未选 proposal 中继续全局取最高分；若该区已有 3 个则跳过。
3. 直到严格得到 K128；每区最终数量必须在 `[1,3]`。
4. 未选的 128 个 proposal 按相同排序构成 reserve queues。

分配器不得读取 GT、fine top8 或后续仿射结果。

## 6. Fine Search、Verifier 与替换

对 K128 primary 计算 exact cosine top8 over 4096 targets。每个 anchor 的 post-search 特征固定为：
pre logit、top8 cosine scores、top1-top2 margin、softmax(score/0.1) entropy、top4 mass、fine top1
xy、coarse top1 cell 映射到 stride-8 后与 fine top1 的 L-inf 距离。

`PostSearchVerifier` 固定为 `Linear(d,32)-GELU-Linear(32,32)-GELU-Linear(32,1)`，以同一
recoverable 标签训练 class-balanced BCE；
训练时使用 train split M256 的 exact fine-search cache。推理替换规则固定为：

1. primary 中 `p_post < 0.5` 的点按 `(p_post,region_id,proposal_id)` 升序处理。
2. 为该点取同区域尚未使用且 pre probability 最高的一个 reserve，执行一次 exact fine top8。
3. 仅当 `p_post(reserve) >= p_post(primary)+0.05` 时替换，否则保留 primary。
4. 每个 primary 最多尝试一次、每个 reserve 最多使用一次、全局最多尝试 R64。
5. 不跨区域替换，不进行第二轮，不因仿射结果追加搜索。

最终仍严格 K128。fine-searched anchors 最少 128、最多 192。

## 7. Oracle 隔离评估

对最终 K128，GT 仅在 evaluator 中执行：保留 recoverable anchors，并从各自 top8 中选择离 GT
target 最近的 candidate；若少于 12 对、source 覆盖少于 3 个象限或 normalized design condition
大于 20，则该 pair oracle invalid。其余使用 FP32 ordinary LS，解析 `512x512` affine flow，与
raw truth_flow 按公开全图无-mask协议计算 AEPE/CMR/PairLocalReady/grid metrics。

recoverable 的距离固定为 stride-8 target 坐标中的 Euclidean L2 `<=2`。normalized design 对
source pixel 使用 `xn=2x/511-1, yn=2y/511-1`，condition 为未加 ridge 的 `X^T X` 2-norm condition。

该结果命名为 `selected-anchor top8 GT oracle`，禁止省略 oracle 字样或与部署结果并列宣传。

## 8. 对照与消融

- `fixed-public-K128`：E-003A 固定 public-stratified K128，同协议重算。
- `uniform-region-K128`：每区固定选择 offset `(2,2)` 与 `(6,6)` 两个主对角 proposal，严格
  得到 K128，不训练。不得改用另一个对角、按分数选择或在结果后更换该对照。
- `source-only-pre`：pre head 去除全部 coarse SAR features。
- `pair-pre-no-coverage`：pre head 全局 top128，不设区域约束，仅作退化诊断。
- `CAAB-no-replacement`：正式动态分配，关闭 post replacement。
- `CAAB-R64`：正式主配置。

主 seed `20260805`；`20260806/20260807` 只报告稳定性，不能替代主 seed。禁止搜索 M、K、R、
region 数、区域上下限、网络宽度、阈值或 replacement margin。

pre/post heads 分别训练，均使用 AdamW、lr `1e-3`、weight decay `1e-4`、pair batch `32`、最多
`50` epochs；以 dev BCE patience `8` early stop。两个 head 都只更新自身参数。训练 fine cache
可包含 M256 exact top8，但 GT label 必须独立存放；正式 inference trace 仍受 192 fine-search 上限约束。

## 9. 自动验证与审阅

顺序固定：archive/split/provenance -> proposal/region property tests -> coordinate/top8 parity ->
GT/path negative tests -> allocation/replacement property tests -> cache differential -> P0 定向实现审阅 ->
P0 oracle；P0 PASS 后才实现/验证 heads -> gradient/toy overfit -> 两轮定向增量审阅 -> watchdog
train/dev -> G1 -> G2 -> RESULT_CARD。P0 FAIL 也必须由 reviewer APPROVE oracle/candidate/metric 路径后
才能作为方法负面结论。

第一 reviewer 审方法语义、标签隔离、区域分配、梯度和替换轨迹；第二 reviewer 审 oracle evaluator、
计时同步、显存、score-count 和 provenance。冻结 GDROS SHA 未变化时不重审其实现。

## 10. Gate

### P0 Proposal Oracle Headroom

在完整 dev 上为 M256 离线计算 exact top8 与 GT 标签，仅作进入训练前的上限检查。使用相同区域
`[1,3]` 约束、以 GT recoverable 优先且 nearest-GT candidate error/固定 ID 打破平局选 K128：

- mean recoverable count 相对 fixed-public-K128 至少增加 20；
- mean recoverable count 相对 uniform-region-K128 至少增加 10；
- selected recoverable fraction `>=50%`，median recoverable count `>=64`；
- selected-anchor top8 GT oracle AEPE `<=2.5 px`、PairLocalReady `>=99%`；
- oracle valid pairs `>=99%`，所有区域覆盖与 source design condition `<=20`。

任一失败则停止，不训练 heads。

### G0 实现资格

- 自动测试、toy overfit、cache parity、GT/路径隔离全部 PASS。
- 两轮 reviewer `APPROVE/APPROVE`。
- 无 GDROS gradient、hidden full correlation、candidate consensus 或超预算替换。

### G1 Anchor Acquisition

主 seed、完整 dev、完全无 GT selection/replacement：

- CAAB-R64 final recoverable fraction `>=50%`，median recoverable count `>=64`；
- 相对 uniform-region-K128 的 recoverable fraction 提升至少 `10 pp`；
- 相对 CAAB-no-replacement 的 recoverable fraction 提升至少 `3 pp`；
- selected-anchor top8 GT oracle AEPE `<=2.5 px`、PairLocalReady `>=99%`、valid pairs `>=99%`；
- 每区 `[1,3]`、最终 K128、fine search `<=192`、全部轨迹 finite 且确定性；
- 三 seed 同方向，主 seed 不得由其他 seed 替代。

报告 precision/recall/AUROC/AUPRC、区域预算直方图、replacement accept rate、recoverable gain、
condition、oracle gap，以及按位移/旋转/尺度/黑边/纹理分组的 bootstrap 95% CI。

### G2 资源

独立进程、batch1、CUDA synchronize、保存 raw timing：

- coarse scores 精确 `256x256`；fine scores 最多 `192x4096`，不得 materialize `4096x4096`；
- anchor acquisition p50/p95 `<=6/10 ms`，增量 warm allocated `<=96 MiB`；
- slim end-to-end p50/p95 `<=18/25 ms`，cold/warm allocated `<=284 MiB`；
- 同进程 GDROS p50 speedup `>=5x`，5 fresh processes p50 CV `<=5%`。

anchor acquisition 从已生成的 frozen `64x64` source/target features 开始，包含 coarse pooling、
coarse scores、pre head、allocation、全部实际 fine searches、post head 和 replacement。slim end-to-end
从解码后的两幅 GPU 输入开始，包含冻结 feature forward 与完整 anchor acquisition。计时均先 warmup
20 次、measured 200 次；每次前后 CUDA synchronize。显存使用 reset_peak 后的 peak allocated，
同时报告进程 cold peak，禁止以缓存跨 pair 结果加速。

## 11. 停止规则

- P0 FAIL：动态 proposal 上限不足，停止并返回方法任务。
- G0 FAIL：只修实现；复核后重跑对应 gate。
- G1 FAIL：当前 CAAB/replacement 停止，不加入 RG-SAC 救援。
- G2 FAIL：当前 anchor acquisition 不满足轻量化，停止且不得事后减 M/K/R。
- 全 PASS：写 RESULT_CARD 并等待用户；不得自动启动 RG-SAC、E-004B 或最终测试。
