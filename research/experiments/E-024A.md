# E-024A：Role-Separated Recurrent Coarse-to-Fine Affine Matcher

方法版本：`M001 v2.8 prototype`

状态：`USER_APPROVED / READY_FOR_ENGINEERING`

## 1. 目标

E-024A 验证一种角色分离的递归 coarse-to-fine affine matcher。它不是 LoFTR 式一次性
`coarse -> fine`，也不是 E-023A 式同构递归，而是每一轮解决不同错误：

```text
R0: coarse basin generation
R1: wide local capture
R2: geometric consensus / outlier rejection
R3: narrow refinement
```

目标是在不恢复 GDROS dense flow state / dense GRU 的前提下，让 fine local observations 反向更新
low-dimensional affine state，并由更新后的 state 重新定义下一轮 local search。

## 2. 输入与边界

- 官方 train/dev split：train `1607`，dev `404`。
- 原始 `512x512` optical/SAR。
- stride-8 tokens：`64x64=4096`。
- 可使用 raw/log-SAR、gradient/census/structure、E-024A 专属 trainable features、frozen DINO feature。
- truth_flow 仅用于 train loss、synthetic/diagnostic label 与 metric；dev inference 禁止读取。

禁止：

- fixed DINO-K256 selector primary path；
- dense flow state；
- dense GRU；
- RANSAC、三点采样、131k hypothesis enumeration；
- hidden new full `4096x4096` stride-8 cross-image tensor；
- OS424/confirm/datum；
- 修改或 finetune DINO/GDROS/baseline checkpoint；
- 写入/污染 E-015A~E-023A 历史产物；
- 自动启动 E-024B/rescue/加速版。

## 3. 方法

### R0：coarse basin generation

R0 解决“是否进入正确 basin”：

- 构建 `1/16` 或 `1/8` low-res tokens/regions；
- 允许 low-res all-to-all correlation/cross-attention；
- 输出 `B<=16` 个 affine/region basin；
- 每个 basin 包含 affine matrix、confidence、coverage、region support；
- 支持 multi-basin oracle-min loss 和 no-GT selected basin head；
- R0 不能使用 truth_flow/datum/OS424/confirm 做 inference。

必须记录：

- selected initial basin AEPE/CMR；
- oracle-best initial basin AEPE/CMR；
- selected-vs-oracle gap；
- region/quadrant coverage。

### R1：wide local capture

R1 解决“真值是否落入窗口”：

- 用 R0 state warp region-balanced anchors；
- window 使用 `33x33` 或 `17x17` token window，允许分块；
- 输出 per-anchor local topK distribution、dustbin、uncertainty、residual candidates；
- 目标优先是 recall/window coverage，而不是 top1 precision。

必须记录：

- GT endpoint window-hit mean/P10/P50/P90；
- selected basin 与 oracle basin window-hit；
- local candidate count 和 in-window oracle upper bound。

### R2：geometric consensus / outlier rejection

R2 解决“窗口中 hard negatives 太多”：

- 用 set/graph/attention consensus 聚合 local candidates；
- 显式使用 displacement consistency、affine residual、region-balanced support、quadrant coverage、
  target collision suppression、dustbin/outlier；
- 每 source 最多一个 active target，可保留 unresolved；
- 用 region-normalized weighted affine update 或等价 differentiable update；
- updated state 必须改变 R3 search center。

必须记录：

- active count、coverage、region/quadrant support；
- residual distribution；
- predicted update improvement；
- oracle update comparison；
- outlier contamination proxy。

### R3：narrow refinement

R3 解决“最终精度”：

- 用 R2 updated state 开 `9x9` 或 `5x5` narrow window；
- 预测 local residual/sub-token refinement 与 confidence；
- 输出 final affine / sparse observations / optional affine flow grid。

必须记录：

- final AEPE/CMR/PLR；
- R2 -> R3 improvement；
- confidence calibration；
- failure buckets。

## 4. Gate

### P0：implementation and isolation

必须 PASS：

- frozen SHA、split、baseline readonly；
- no OS424/confirm/datum；
- no dense flow state / dense GRU；
- no fixed DINO-K256 selector primary path；
- no RANSAC/三点/131k；
- no hidden new full `4096x4096` stride-8 tensor；
- R0/R1/R2/R3 role trace；
- each round has distinct loss/metric；
- R1/R3 window-size trace；
- recurrent state changes next-round search centers；
- truth_flow only train/metric；
- train/dev no-GT inference separation；
- coordinate direction、stride-8、window sampling tests。

P0 fail：`IMPLEMENTATION_BLOCKED`。

### G0：train mechanism sanity

只用 train/synthetic，不使用 dev 后验。必须 PASS：

- synthetic affine/perturbation `>=100` PASS；
- gradients to R0/R1/R2/R3 required modules；
- strict checkpoint load；
- train no-GT inference finite；
- R0 train oracle-best initial AEPE <= `15 px` 或显著优于 E-023A train reference；
- R1 train window coverage >= `80%`；
- R2 train predicted update improves over R1 by >= `25%`；
- R3 train final AEPE improves over R0 selected by >= `40%`；
- no baseline writes / no forbidden modules。

G0 fail：`ROLE_SEPARATED_TRAIN_FAIL`，不跑 dev404。

### G1：dev404 effectiveness

G0 PASS 后运行 dev404 no-GT inference。资源只诊断。

判读：

- `COARSE_BASIN_FAIL`：R0 oracle-best dev AEPE > `15 px` 或 selected initial AEPE 未比 E-023A `50.546 px` 改善 `>=25%`；
- `WINDOW_CAPTURE_FAIL`：R1 dev window coverage < `80%`；
- `CONSENSUS_OUTLIER_FAIL`：R1 coverage >= `80%` 但 R2 update 未改善 `>=25%` 或 outlier contamination dominates；
- `REFINEMENT_FAIL`：R2 已进入 `<=20 px`，但 R3 final 未改善；
- `WEAK_ROLE_RECURRENT_FOUND`：final AEPE 比 E-023A `50.578 px` 改善 `>=25%`，但 > `20 px`；
- `COARSE_TO_FINE_MATCHER_FOUND`：final AEPE <= `20 px` 且 CMR@5 >= `25%`，PLR >= `50%`；
- `USEFUL_ROLE_RECURRENT_FOUND`：final AEPE <= `12 px` 且 CMR@2 >= `20%`，PLR >= `70%`；
- `STRONG_ROLE_RECURRENT_FOUND`：final AEPE <= `5 px` 且 CMR@2 >= `50%`，PLR >= `90%`。

必须比较：

- E-023A final AEPE `50.578 px`；
- E-023A-DIAG oracle endpoint best-update AEPE `6.206 px`；
- E-022A selected-set AEPE `34.001 px`；
- dense GDROS reference if available, readonly only。
