# E-029A：E-028B Frontend + GDROS-Style Backend Joint Adaptation

方法版本：`M001 v3.4 prototype`

状态：`USER_APPROVED / READY_FOR_ENGINEERING`

## 1. 目标

E-029A 验证用户提出的第一条系统级路线：用 E-028B safe dual-adapter feature frontend 替换 GDROS 的特征提取
部分，并让替换后的 frontend/bridge 与 GDROS-style 后半段一起训练，使后端适应我们的特征分布。

核心问题：

> E-028B feature 接入强匹配后端并联合训练后，能否显著缩小与 GDROS full system 的差距？

本实验不是轻量匹配器实验；轻量匹配器作为后续方向，不能自动启动。

## 2. 已知对照

- `E028B_SAFE_DUAL_ADAPTER_FAIR`：AEPE `21.418`，recall@2 `0.669`，correct@2 `0.520`；
- `GDROS_FEATURE_FAIR`：AEPE `96.430`，recall@2 `0.729`，correct@2 `0.762`；
- GDROS full system / baseline-init diagnostic reference：AEPE 约 `1.47`；
- 完整 baseline reference 必须标注来源、SHA、是否 exact replay。

## 3. 数据与边界

- train/dev split：train `1607`，dev `404`。
- 原始 optical/SAR 固定 `512x512`。
- `truth_flow` 只用于 train loss、label 和 metrics。
- `datum` 仅做 archive 完整性/SHA，不作为标签。
- OS424/confirm 禁止参与。
- 原始 GDROS baseline 代码/checkpoint/cache/run 只读。
- E-028B formal checkpoint 只读；若 trainable frontend，必须复制到 E-029A checkpoint 后训练。

## 4. Tracks

### A. `GDROS_FULL_BASELINE_REFERENCE`

- 只读引用或等价 replay；
- 记录 source、SHA、config、是否 exact full baseline；
- 若 exact replay 不可用，标注 diagnostic reference，不得伪称追平。

### B. `E028B_FAIR_MATCHER_REFERENCE`

- 读取 E-028B 正式 feature-only fair matcher 结果；
- 用于判断系统接入是否超过 feature-only 起点。

### C. `FROZEN_E028B_FRONTEND__TRAINED_GDROS_BACKEND`

```text
frozen E-028B frontend
-> trainable bridge adapter
-> trainable copied GDROS-style backend
-> flow / affine / metrics
```

### D. `TRAINABLE_E028B_FRONTEND__TRAINED_GDROS_BACKEND`

```text
E-028B frontend copy initialized from formal checkpoint
-> trainable bridge adapter
-> trainable copied GDROS-style backend
-> flow / affine / metrics
```

必须保护 E-028B formal checkpoint 不被修改。

## 5. 训练目标

必须包含：

- endpoint / flow supervision；
- matching/correlation loss；
- iterative update 或 multi-scale loss（若 backend 支持）；
- affine/grid auxiliary loss；
- trainable frontend copy 的 teacher consistency，防止远离 E-028B safe representation；
- strict load、gradient audit、finite train no-GT inference。

## 6. 评价

Formal dev `404` 必须报告：

- AEPE；
- CMR@1/2/5；
- PLR；
- finite / in-bounds；
- runtime p50/p95/max；
- peak memory；
- train/dev gap；
- 与 GDROS full baseline reference 的差距；
- 与 E-028B fair matcher reference 的差距。

## 7. Gate

### P0：implementation and isolation

必须 PASS：

- GDROS baseline readonly；
- E-028B formal checkpoint readonly；
- GDROS-style backend copy 与 baseline 隔离；
- E-028B frontend replacement path 真实喂入 backend；
- bridge shape/normalization 记录；
- no baseline writes；
- no OS424/confirm/datum；
- feature/flow materialized before truth_flow metric join；
- train/dev split isolation；
- source/checkpoint SHA 完整。

P0 fail：`FRONTEND_BACKEND_INTEGRATION_IMPLEMENTATION_BLOCKED`。

### G0：training sanity

必须 PASS：

- frozen/trainable frontend tracks 至少一个完成训练；
- train loss finite/decreases；
- gradients 到达 bridge/backend，若声明 trainable frontend 则到达 frontend copy；
- strict checkpoint load；
- train no-GT inference finite；
- copied backend parity 或 sanity pass；
- reviewer 对 isolation/training approve。

G0 fail：`FRONTEND_BACKEND_TRAINING_BLOCKED`。

### G1：formal dev system comparison

判读：

- `NO_SYSTEM_INTEGRATION_GAIN`：best E-029A system 未超过 E-028B fair matcher 或不稳定；
- `BACKEND_ADAPTATION_GAIN_FOUND`：best system 相对 E-028B fair matcher AEPE 改善 `>=25%`；
- `GDROS_GAP_SUBSTANTIALLY_CLOSED`：best system AEPE `<=5 px` 或达到 GDROS full reference `<=3x`；
- `GDROS_SYSTEM_APPROACHED`：best system AEPE `<=3 px` 或达到 GDROS full reference `<=2x`；
- `GDROS_SYSTEM_MATCHED_OR_BETTER`：best system 在 reviewer-approved tolerance 内追平/超过 GDROS full reference；
- `IMPLEMENTATION_OR_BASELINE_REFERENCE_BLOCKED`：baseline/reference 歧义阻止系统级 claim。

## 8. 审阅

blocking finding：`IMPLEMENTATION_BLOCKED`。
