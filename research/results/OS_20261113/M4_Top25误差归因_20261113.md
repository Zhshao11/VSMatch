## 3. 归因判断

### 结论：瓶颈在**跨模态特征匹配层**（E072/E073 双前端 + 相关体融合产生的稠密对应），
### 不是 LSR 几何重建，区域门控只是次要损失。

**① LSR 几何重建 —— 排除（证据最强）**
- Top-25 的 `ΔLSR` 平均仅 **+0.0287**，23/25 对 `|ΔLSR| < 0.5`：LSR 既没把好的流变坏，也没能力把坏的流修好。
- 拟合出的尺度/旋转几乎正确（`ds = −0.017`、`dθ = −0.225°`），仿射拟合本身没跑偏。真正错的是**平移**（`t_err = 16.64 px`，`α = 0.80`），而平移来自网络 raw flow 的全局位移，LSR 只是忠实地把它拟合成仿射场。
- 与既有 `鲁棒仿射验证结果.md` 一致：IRLS / trimmed-LS 对灾难配对几乎无效（13.31→13.17），说明不是"离群污染拖偏最小二乘"，换拟合器救不了。

**② 区域门控 —— 次要因素，不是主因**
- `gate_mean` 0.6576 vs 0.6515：门控在灾难对上的**行为与正常对几乎相同**，没有塌缩或异常；只是 std 略大（0.2012 vs 0.1494）。
- 逐像素 oracle(B,C) 仍高达 **9.1815**（20/25 对 >5px），即两支都错时门控再准也无解。把门控换成 oracle 最多把 11.28 降到 9.18，仍是灾难级。
- 但确有**局部选错支**：`gate_gap > 1` 的有 15/25，典型如 `000241`（B=4.400、C=19.277，gate=0.653 偏 C，M4=14.161、oracle=4.397）、`000213`、`000380`、`000101`、`000404`。这些是门控可优化的点，但属二阶收益。

**③ 跨模态特征匹配 —— 主因**
- **LSR 前就错**：Top-25 的 `epe_pre = 11.2481`（25/25 对 >5px），误差在进入任何后处理之前已经存在。
- **两支同时失效**：B 10.26 / C 11.86 / oracle 9.18，说明不是某一支的偶然失误，而是两条链路共享的前端/教师栈共同盲区（与 `CMR_现象记录.md` 的 oracle CMR@5=91.22 < baseline 93.51 一致）。
- **不是数据集本身难**：GDROS 官方权重在同一 25 对上平均只有 **1.2595**（比它自己的全量均值 1.4618 还好），22/25 对 <2px。同样的图像对，换成另一套前端就能配准 → 失败是 M4 前端特有的。
- **失败高度集中在 1.10 尺度档**：23/25 对 `gt_scale≈1.10`，该档 123 对里有 23 对 EPE>5px，其他三个尺度档合计只有 2 对。
- **具体机制是平移估计错，不是尺度/旋转**：`α = 0.8022`（其余 0.9998），15/25 对 `α<0.9`，最差 `000116` α=0.21、`000280` α=−0.31（方向反了）、`000166` α=0.38。即网络估出的全局位移只有真值的 ~0.8 倍甚至反向；`ds`、`dθ` 基本为 0。这与 `OS_方法汇报.md` §3.1「平移向内收缩、迭代停在第 2 步后的伪不动点」以及 `greach.py` 的记录一致。
- raw 流非仿射残差 2.29（其余 0.70），也说明网络输出的对应场本身混乱，而非"正确的对应被 LSR 压成错的仿射"。

> 注：不是所有 Top-25 都是"收缩"。`000163`（α=1.92，gt_scale=1.000）、`000070`（α=1.13，0.900 档）是**平移过冲**，属另一类失败，说明 1.10 档是主病灶但不是唯一病址。

**一句话**：Top-25 是「1.10 尺度档的平移估计失效」造成的配对级灾难；它发生在
E072/E073 的跨模态稠密对应阶段，B/C 两支共同继承了这个错误，区域门控只能在
坏与更坏之间取舍，LSR 则无辜。要压尾部，应从**前端匹配 / 迭代收敛**（难度递增合成、
1.10 档针对性覆盖）入手，而不是继续调门控或仿射拟合。
