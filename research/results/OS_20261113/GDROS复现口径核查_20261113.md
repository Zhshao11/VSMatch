## 2. 根因：`test.py` 算的不是端点误差，而是逐分量绝对误差

官方 `test.py`：

```python
epe = torch.sum((flow_pre - flow_gt)**2, dim=0).sqrt()
```

实测张量形状：`flow_pre (1,2,512,512)`、`flow_gt (2,512,512)`、`diff (1,2,512,512)`。
广播后在 **dim=0（batch 维）** 求和开方 → `[2,512,512]`，即 `|Δx|`、`|Δy|` 两个分量。
正确的端点误差应是 `sum(dim=1).sqrt()` 或 `linalg.vector_norm(diff, dim=1)`。

我们项目里 `eval_os_unified.py` / `eval_os_full_metrics.py` / E075A `eval_model` 用的正是
`linalg.vector_norm(..., dim=1)`，即真正的 EPE。两者不可比。

**同一批预测流、只换误差定义**（`diag_gdros_epe.py`，424 对，36.6 s）：

| 误差定义 | AEPE | CMR@1(配对) | CMR@2 | CMR@5 | var(配对均值) |
|---|---|---|---|---|---|
| A 官方 `test.py`：逐分量 `|Δx|,|Δy|` | **1.461846** | **33.726** | 81.604 | 99.528 | 0.7463 |
| B 向量 EPE `sqrt(Δx²+Δy²)` | 2.321585 | 9.434 | 52.123 | 94.340 | 1.9169 |

`AEPE_B / AEPE_A = 1.5881`，与各向同性误差下的理论比 `π/2 = 1.5708` 一致。
阈值施加在更小的分量误差上，CMR@1 自然从 9.43 抬到 33.73。
逐像素 CMR@1 也同向：A 46.95%、B 18.43%（对应官方打印的 `1px: 0.469459`）。

## 3. 官方/论文里另外两处「名实不符」（报数时务必注意）

1. **官方 "RMSE" 是方差**：`RMSE = np.var(MAE_list)`，没有开根号。论文公式 (15) 写的是
   带 sqrt 的标准差，但表格 OS `RMSE 0.75±0.02` 对应的是方差 `0.7463`（`sqrt` 后是 0.864）。
   即论文表格的数字跟代码走，公式文字与数字不一致。
2. **论文正文声称 EPE 是 "averaged pixel-wise Euclidean distance l2"**，但表格数字与官方代码
   （逐分量误差）一致，与 l2 范数口径不一致。要引用论文数值，必须按官方代码口径。
3. `CMR@τ` 是**配对级**（`EPE(k)<τ` 的图像对占比），不是逐像素；`AEPE@τ` 是通过阈值配对的
   EPE 均值（inlier-mean，与我们今早脚本实现一致）。官方打印的 `1px/3px/5px` 那一行才是逐像素。

## 4. 已排除的疑点（逐项核实，不是猜测）

| 疑点 | 核实结果 |
|---|---|
| 权重不对 | 官方 `test.py` 用同一个 `GDROS-os512.pth` 复现论文/REFS 数字，权重正确 |
| 数据集版本不对 | `official_archives/gdros/testing.zip` 与 `extracted/gdros_official_e003a_testing/testing` 结构一致：424 对，`opt/sar_warped/truth_flow/datum` 各 424；`truth_flow/scene/` 另有 424 个副本，`glob('*.flo')` 只取根目录 424 个并与 `opt/*.png` 按序对齐，无错位 |
| 模型配置不对 | `configs/default.py` 默认 `transformer='featureformerwithlbl'`，与我们手动设置一致；`image_size=[512,512]` 与官方 `test.py` 一致 |
| `LSRnet.pth` 没加载 | 官方 `test.py` 也不加载它；`LSR()` 走无权最小二乘 `LSR_()`，只用 `[10000:10000+Npoint]` 个点拟合。该文件与推理无关 |
| LSR / iters / mask | `Npoint=200000`、`iters=32`、`test_mode=True` 一致；valid mask 实测全 1，官方忽略 mask 与我们的 masked 统计等价 |

## 5. 需要更正的历史结论（此前判断是错的）

- `OS复现结果.md` §2：「这是真实差距，不是评测脚本 bug」「1.461 极可能是 GDROS 论文公布的
  OS 数字，而非本机 `GDROS-os512.pth` 在该提取测试集上的实测值」→ **错**。1.461 就是本机
  checkpoint 在同一数据集、用官方口径的实测值；差距 100% 来自误差度量定义。
- `OS_方法汇报.md` §4 第 2 点「这是 checkpoint 与测试集版本的差异，不是脚本 bug」→ **错**，同上。
- `OS_全指标评测_20261113.md`（今早）：标为「官方配对级口径」的表实际是
  **配对级聚合 + 向量 EPE** 的混合口径，不能与论文/REFS 数字对照；文中「与官方 `test.py`
  无掩码统计等价」仅对 mask 成立，对 EPE 不成立。

正确表述应为：**同一脚本、同一口径下 baseline 与自研方法可比；但与论文表格对比时必须
统一到官方 `test.py` 口径，或明确声明用了 l2 EPE 口径。** 此前所有「baseline 弱于论文」的
说法作废。

## 6. 对后续对比的影响（本次按要求未跑自研方法）
