# M4 的耗时与 CMR@1 收益来自哪里（E098A）

2026-11-16。结论：当前 CleanM4 的主要成本是三套迭代匹配器、冻结 DINO 和重复的特征前端；内部四次 LSR 是较小的成本。当前 C/student 分支单独就具有明显的 CMR@1 优势，完整 B/C 融合在其基础上继续提升。现有证据尚不能把 C 分支的收益拆分归因于 DINO、双相关金字塔、蒸馏或训练配置。

本轮没有训练、修改权重或改变默认架构，也没有执行 Git 提交或推送。

## 1. 耗时拆解：主要成本在匹配和特征

此前 E096A 全量 OS424 同轮计时：官方 GDROS 为 **221.343 ms/对**，CleanM4 为 **571.037 ms/对**，约 **2.58 倍**。这是完整评测的结果；下表是新做的小规模组件诊断，不能将其中毫秒数或占比直接拼接到此前全量耗时上。

新诊断使用共享 GPU5，固定 10 对、每种模型 3 次预热与 3 次正式重复，FP32、512×512、batch=1、32 次迭代。粗粒度 CUDA event 范围经嵌套扣除后互不重叠：

| 组件 | M4 / ms | GDROS / ms | 占 M4 诊断总时长 | 占相对 GDROS 额外时长 |
|---|---:|---:|---:|---:|
| 迭代匹配及相关操作 | 294.947 | 190.438 | 60.57% | 38.69% |
| 冻结 DINO 特征 | 86.576 | 0 | 17.78% | 32.05% |
| 特征前端 | 59.577 | 11.155 | 12.23% | 17.93% |
| 全部 LSR | 26.532 | 6.714 | 5.45% | 7.34% |
| 其余上下文、适配、建金字塔、门控等 | 19.327 | 8.557 | 3.97% | 3.99% |
| 合计 | 486.958 | 216.863 | 100% | 100% |

前三类解释本轮额外时长的约 **88.7%**。这里“迭代匹配”包含相关性查询、motion encoder、GRU、位移预测、mask/上采样和匹配器内部其他操作，**不是纯 GRU 算子时间**。表中 CUDA event 是流上的经过时间，包含调度/CPU 间隙，不是所有 GPU 内核活跃时间的加总。

每对实际调用计数进一步解释了成本来源：

| 操作 | CleanM4 | 官方 GDROS |
|---|---:|---:|
| 完整迭代匹配器 | 3 | 1 |
| GRU 更新 | 96（3×32） | 32 |
| 特征前端调用（一次处理一对图像） | 6 | 1 |
| DINO forward_features | 2（两幅图，已共享） | 0 |
| 四层相关金字塔 | 5 | 1 |
| 各层相关性双线性采样 | 640 | 128 |
| mask head / 学习上采样 | 3 / 3 | 32 / 32 |
| LSR | 5 | 1 |
| 外部融合门控 | 2 | 0 |

即使已经删除无用分支和中间上采样，当前 M4 仍保留 B 内的 F2、F3 与 C/student 三套有效匹配计算。建相关金字塔本身在本诊断中很快；反复查询金字塔的成本归入迭代匹配。门控网络本身合计约 0.72 ms，但为了给最终门控提供 B，必须计算其两套完整匹配器；不能仅因门控卷积便宜就认为整条融合路径便宜。

粗粒度协议中，未插桩同步墙钟均值为 M4 492.728 / GDROS 221.610 ms；插桩墙钟为 486.998 / 216.905 ms。两阶段处于共享负载下，均值差异不能解释为“负插桩开销”。细粒度协议插入大量 event，明显扰动时间，因此仅用其核对调用数，不采用其组件占比作为结论。粗粒度诊断也不替代独占部署基准。

## 2. 为什么四次 LSR 只省十几毫秒

当前调用的官方 `LSR_` 是六参数仿射位移拟合：输入设计矩阵为 N×3，位移为 N×2，形成 **3×3** 正规矩阵和 3×2 右端项。虽然采集 200,000 个点，但不是求解 200,000×200,000 的线性系统。完整函数还重建稠密网格并执行 CPU/GPU 数据转换，所以有成本；它没有三套特征提取与 96 次循环更新的成本大。

E097A 全量固定权重消融：5 次→仅最后 1 次，使本轮均值从 354.466→337.404 ms，省 **17.062 ms / 4.81%**。其绝对耗时来自共享 GPU7，不能与上表 GPU5 直接做毫秒加减。

此前 E094A 的 129→5 不只是移除 124 次拟合，还同时省掉 **62 次中间 B/M4 门控前向及配套全分辨率输入构造**。因此不能把那次全部加速归因于 LSR。

## 3. 内部 LSR 并非仅影响 >5 px

E097A 删除内部四次拟合时，以原始流代替拟合流、相应残差置零，保留全部权重。原方案与仅最终拟合方案分别为：

| 指标 | 原 5 次 | 仅最后 1 次 | 变化 |
|---|---:|---:|---:|
| CMR@1 | 72.4057% | 71.4623% | 净少 4 对成功 |
| CMR@5 | 94.1038% | 93.6321% | 净少 2 对成功 |
| 平均分量误差 | 1.474418 px | 1.510790 px | +0.036372 px |

全部 424 对预测都改变了，阈值成功数只反映跨线情况，不能表述成仅有几对变化或只影响尾部。另一方面，删除后 CMR@1 仍为 71.46%，所以内部四次 LSR 显然不是相对 GDROS 提高约 39 个百分点的主要来源。该消融改变已训练门控的输入分布，不等于重新训练一个无 LSR 输入架构后的结果。

## 4. 高 CMR@1 的收益已能定位到 C 分支整体

本轮重新审计历史 E093A 预测缓存，验证四套清单、全部 **1,696 个预测文件哈希**，并确认其中 M4 与已接受的 E096A 在 **424/424 对逐元素完全一致**，再从 GT 重算指标。这是新的缓存审计，不是本轮重新推理 B/C。原 E093A 因旧 E092A 回归不一致而失败的状态和文件均保留。

所有分支使用受保护 M4 step80K 中的对应有效权重、32 次迭代及最终官方 LSR；指标是同一 OS424 公共分量口径，CMR 为每对均值严格小于阈值的比例：

| 路径 | 平均分量误差 / px | CMR@1 | 成功对数 | CMR@5 |
|---|---:|---:|---:|---:|
| GDROS（E096A 全量新推理） | 1.461661 | 33.7264% | 143 | 99.5283% |
| B 单独 | 1.580882 | 58.4906% | 248 | 94.3396% |
| C/student 单独 | 1.592903 | 69.5755% | 295 | 92.9245% |
| B/C 原始流等权平均，再最终 LSR | 1.486691 | 69.3396% | 294 | 93.8679% |
| 完整 M4 | 1.474418 | 72.4057% | 307 | 94.1038% |

- C 单独相对 GDROS 已高 **35.85 个百分点**；完整 M4 相对 C 再高 **2.83 个百分点，净多 12 对**。
- 完整 M4 相对等权 B/C 平均高 **3.07 个百分点，净多 13 对**，说明外层学习融合在当前权重条件下还有增益。
- B 也有精度优势，不能把全部收益归给 C；上述差值不是可加的独立模块因果贡献。
- C 是包含双路特征、双相关查询、循环更新和训练所得参数的完整匹配器。当前证据不能区分 DINO、双相关、蒸馏/损失及训练预算各自的贡献，更不能把 GRU 本身当成相对 GDROS 的新增创新。
- 完整 M4 的 CMR@5 仍低于 GDROS，平均误差也未优于 GDROS；高 CMR@1 与尾部失败并存。

## 5. 下一步的优先级

优先把 **C/student 单独部署**作为精简基线，独立测量完整耗时，再看保留 DINO/双相关的精度成本。它有希望省掉 B 的两套匹配器，但仍保留 DINO 和自身双路特征，**尚无单独计时，不能声称精确加速几倍**。之后设计训练口径一致的 DINO、双相关和蒸馏消融，才有依据确定下一版架构应保留什么。继续压缩四次内部 LSR 的收益优先级较低。

当前仍保留原 5 次 LSR 默认方案。本轮没有启动上述后续训练。
